# AIエージェント

## ワークフロー  
#### マルチエージェント形式を採用。
それぞれの処理を**チェーン**と捉え、**チェーン同士がつながった**イメージで作成。  
各チェーン内では**エージェント ( エージェント内でツールを使う場合もあり )** や**スクレイピング操作**の処理が動いている。

![エージェントタイプ図](image/agent_workflow.png)

### 司令 ( orchestrate )
全体の指揮をとる。

- **司令 (orchestrate)**  
  最新1件のメッセージ履歴から**次に実行するチェーンを決定**する。  
  LangChainにおけるスーパーバイザー。
  - 司令エージェント
  - エージェント呼び出しツール

### 戦略決定 ( strategy )
人材調査の戦略を立てる。

- **スキル分析 (skill_analyze)**  
  ユーザの入力にある要件から、その要件を満たす人材に必要なスキル・経験を分析する。
  - スキル分析エージェント
  - Web検索ツール

- **サイト選択 (select_site)**  
  分析したスキル・経験を持っている人材はどのサイトからなら見つかりそうか探す。
  - サイト選択エージェント
  - Web検索ツール

### 調査 ( research )
人材調査をする。

- **調査 (research)**  
  与えられたサイトから目ぼしい人材を調査
  - スクレイピング
  - 調査エージェント

- **データ整形 (date_shape)**  
  調査結果をまとめる
  - データ整形エージェント

- **追加調査 (additional_research)**  
  見つけた人材をについてさらに調査
  - スクレイピング
  - 追加調査エージェント

### 推薦 ( recommend )
調査結果から有望な人材を推薦する。

- **推薦 (recommend)**  
  調査した人材を評価軸に基づいてスコアリングし、その結果から今回の要件に有望な人材を推薦する。
  - 推薦エージェント

## マルチエージェント形式の選定理由
#### 単体エージェントに指示するには工程が多すぎたから。
以下はLangChain(LangGraph)で実現できるエージェント形式である

![エージェントタイプ図](image/agent_types.png)

- Single  
  実現不可能
- Network  
  複雑になりすぎる  
  全てがつながる必要性はない
- **Supervisor**  
  司令がいるので複数のエージェント管理がしやすそう  
  細かな指示ができないかもしれない  
  試してみたが、パイプライン制御はSupervisor次第(**プロンプト文のみでの制御次第**)であり、**複雑なワークフロー構築には限界がありそう**  
  全てを司令に送るのはトークン問題が心配
- Hierarchical  
  Supervisorの弱点の細かな指示も解決できそう  
  複雑なワークフロー構築には相変わらず限界がありそう
- **Custom**  
  今回目的が決まっているので、部分的なワークフローを組んでも良いかもしれない  
  全てを司令に送る必要もなくなるのでトークン問題も少し安心  
  実装が複雑になってしまう恐れ

以上の点から、今回は **Supervisorを混ぜたCustom形式** を採用し、自由なワークフローを構築する。
